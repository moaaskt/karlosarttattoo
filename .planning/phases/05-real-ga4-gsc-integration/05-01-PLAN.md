## 🎯 Objetivo da Fase 05

Conectar o painel administrativo do Karlos Art Tattoo aos dados analíticos do Google (Google Analytics 4 e Google Search Console) utilizando autenticação de Service Account via `google-auth-library` e chamadas REST diretas aos endpoints oficiais.

Apresentar as métricas em uma nova aba dedicada **"Tráfego & SEO"** (`AnalyticsTab.tsx`) na Sidebar do `/admin`, protegida por autenticação, com cache em memória de 30 minutos e fallback automático ultra-realista quando não houver credenciais no `.env`.

---

## 📋 Lista de Tarefas de Execução

### TASK-01 — Dependência `google-auth-library` & Módulo de Autenticação de Service Account
- **Tipo:** infraestrutura & segurança
- **Arquivos:** `package.json`, `src/server/lib/google-auth.ts`, `src/test/analytics-api.test.ts`
- **O que fazer:**
  1. Instalar `google-auth-library` como dependência de produção:
     ```bash
     npm install google-auth-library
     ```
  2. Criar `src/server/lib/google-auth.ts`:
     - Leitura segura das variáveis de ambiente:
       - `GOOGLE_SERVICE_ACCOUNT_EMAIL`
       - `GOOGLE_PRIVATE_KEY` (com normalização de `\n` e suporte a aspas)
       - `GA4_PROPERTY_ID`
       - `GSC_SITE_URL`
     - Função `hasGoogleCredentials(): boolean` para verificar se as variáveis mínimas estão presentes.
     - Função `getGoogleAuthToken(scopes: string[]): Promise<string | null>` utilizando `GoogleAuth` ou `JWT` de `google-auth-library`.
     - Tratamento defensivo de falhas de autenticação sem quebrar o servidor.
  3. Teste unitário comprovando que `hasGoogleCredentials()` detecta variáveis presentes vs ausentes.

---

### TASK-02 — Módulos de Busca GA4, Search Console e Cache em Memória
- **Tipo:** engine de dados & resiliência
- **Arquivos:** `src/server/lib/analytics-cache.ts`, `src/server/lib/google-analytics.ts`, `src/server/lib/google-search-console.ts`, `src/server/lib/analytics-mock.ts`
- **O que fazer:**
  1. `src/server/lib/analytics-cache.ts`:
     - Cache em memória simples com chave composta `analytics:${period}`.
     - TTL padrão de **30 minutos** (1800 segundos).
     - Mecanismo de invalidação sob demanda (`invalidateAnalyticsCache()`).
     - Deduplicação de requisições ativas simultâneas para evitar thundering herd nas APIs do Google.
  2. `src/server/lib/analytics-mock.ts`:
     - Gerador de dados simulados realistas calibrados para o ateliê (cidades de SC: Palhoça, Florianópolis, São José, Biguaçu; termos de busca: "karlitos tattoo", "tatuador palhoça", "estudio tatuagem palhoca", etc.).
     - Retorna flag `is_mock: true` no payload.
  3. `src/server/lib/google-analytics.ts`:
     - Chamada REST para `https://analyticsdata.googleapis.com/v1beta/properties/{propertyId}:runReport`.
     - Consulta métricas de sessões, usuários ativos, page views, taxa de engajamento, cidades e canais de tráfego para os períodos `7d`, `30d`, `90d`.
  4. `src/server/lib/google-search-console.ts`:
     - Chamada REST para `https://searchconsole.googleapis.com/webmasters/v3/sites/{siteUrl}/searchAnalytics/query`.
     - Consulta dimensões `query` e `page`, com métricas de cliques, impressões, CTR e posição média.

### TASK-03 — Rota de API Servidora `GET /api/analytics` com Autorização e Testes
- **Tipo:** API REST & testes automatizados
- **Arquivos:** `src/server/api/analytics.ts`, `src/routes/api/analytics.ts` (ou handler de despacho), `src/test/analytics-api.test.ts`
- **O que fazer:**
  1. Criar handler `handleAnalyticsRequest(request: Request)`:
     - Verificação de autorização com `isAuthorized(request)` (rejeita não autorizados com 401).
     - Validação dos query params: `period` (`7d` | `30d` | `90d`, padrão `7d`) e `force` (`true` | `false`).
     - Se `force === "true"`, invalida o cache em memória antes de consultar.
     - Se `hasGoogleCredentials()` for falso, retorna imediatamente os dados do mock com `is_mock: true`.
     - Se credenciais estiverem ativas, consulta as APIs reais via cache e combina os resultados de GA4 + Search Console.
  2. Testes automatizados em `src/test/analytics-api.test.ts`:
     - Rejeição de requisições sem token (401 Unauthorized).
     - Retorno correto de mock em ambiente de teste com `is_mock: true` e formato de dados validado.
     - Funcionamento do cache com TTL e parâmetro `force=true`.
     - Suíte rodando e integrada ao `npm test`.
